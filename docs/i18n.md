# Internationalisation

L'interface parle français et anglais ([#14](https://github.com/AbderrahmaneMouzoune/onmangekoi/issues/14)). Le chantier est découpé en trois phases :

- **Phase A** (faite) : l'infrastructure (`next-intl`, routage, messages, typage, formatage, erreurs, sélecteur de langue) et le premier lot d'écrans — layout racine, accueil, 404 et erreurs, `/setup`, `/login`, `/offline`, `components/layout`, `components/onboarding`, `components/home`.
- **Phase B** (faite) : les sessions et le carnet de restaurants — `components/session`, `components/restaurants`, les pages `sessions/**`, `duo`, `join/**`, `r/[code]` (images Open Graph comprises), les phrases fabriquées par le domaine de la session, les Server Actions et les schémas de session, de vote, de restaurant et de lieu.
- **Phase C** : le reste de l'interface (liste en fin de document), puis la règle ESLint en `error` sur tout `src/` et les e2e dans les deux langues.

Ce guide est la référence des phases suivantes : il dit où ranger un texte, comment l'appeler, et comment le tester.

## Architecture

### La langue est un segment de route caché

```
navigateur : /join/7K3M9P
  └─ src/proxy.ts   choisit la langue : cookie NEXT_LOCALE, sinon Accept-Language, sinon fr
       └─ réécrit vers /en/join/7K3M9P   (l'URL visible ne change pas)
            └─ src/app/[locale]/(app)/join/[code]/page.tsx
```

- **Aucun préfixe d'URL** (`localePrefix: 'never'`, `src/i18n/routing.ts`) : un lien d'invitation, une liste partagée ou un classement public est le même pour tout le monde. Une URL préfixée (`/en/sessions`) est redirigée vers sa forme sans préfixe.
- **Pourquoi un segment `[locale]` et pas une simple lecture de cookie ?** Les Cache Components prérendent la coquille statique de chaque page. Lire un cookie dans le layout racine (pour `<html lang>`) rend _tout le site_ dynamique : `next build` refuse (« Uncached data was accessed outside of `<Suspense>` »). Avec la langue en paramètre de route, chaque coquille est prérendue deux fois (`/fr/…`, `/en/…`) et reste servie depuis le cache.
- **`src/i18n/request.ts`** lit la langue avec `next/root-params` (le paramètre du layout racine, sans rendre la page dynamique). Là où Next ne le permet pas — Server Actions, route handlers — il retombe sur la requête : l'en-tête posé par le proxy, le cookie, puis `Accept-Language`. Une langue explicite (`getTranslations({ locale, namespace })`) passe avant tout : c'est ce que font les images Open Graph et le manifest.
- **Le proxy passe sur toutes les pages** (matcher dans `src/proxy.ts`), mais ne rafraîchit la session Supabase que sur `SESSION_REFRESH_PREFIXES` (`src/lib/routing.ts`) — l'accueil ou un classement public ne coûtent pas d'aller-retour vers Supabase Auth. En sont exclus : `/api/`, `/_next/`, les icônes, `/sw.js`, les fichiers statiques et les images Open Graph (leur URL contient déjà la langue : `/en/join/…/opengraph-image-…`). Le manifest, lui, y passe : il est traduit.
- **Sélecteur de langue** : pied de page (`components/layout/locale-switcher.tsx`). La Server Action `setLocaleAction` pose le cookie `NEXT_LOCALE` (un an), puis la page se recharge pour repasser par le proxy.
- **404** : une adresse inconnue n'a pas de route sous `[locale]` ; Next sert `src/app/global-not-found.tsx` (statut 404, bilingue, puisqu'elle est statique). Un `notFound()` dans une page existante affiche `src/app/[locale]/not-found.tsx`, dans la langue du visiteur.
- **Erreur globale** (`src/app/global-error.tsx`) : hors de tout provider, elle embarque les messages de `layout.json` et lit la langue dans le navigateur (`readClientLocale`).

### Ce qui reste hors de `[locale]`

`src/app/api/`, `sw.js/`, `icons/`, `icon.tsx`, `apple-icon.tsx`, `robots.ts`, `sitemap.ts`, `nouveautes/rss.xml/` (URL à extension, non réécrites), `global-error.tsx`, `global-not-found.tsx`. Une nouvelle **page** va toujours sous `src/app/[locale]/`.

### Revalider un chemin

Le cache connaît `/fr/sessions/7K3M9P` et `/en/sessions/7K3M9P`, pas `/sessions/7K3M9P`. **N'appelez plus `revalidatePath` directement** : `revalidateLocalizedPath` (`src/i18n/server.ts`) invalide chaque langue, et préfixe les motifs (`ROUTE_PATTERNS.list` → `/[locale]/lists/[code]`). `revalidateTag` et `updateTag` ne changent pas.

## Les messages

```
messages/
  fr/  common.json errors.json layout.json home.json onboarding.json metadata.json og.json pwa.json
       session.json restaurants.json account.json lists.json groups.json legal.json changelog.json
  en/  les mêmes fichiers
```

- **Un fichier par espace de noms**, assemblés dans `src/i18n/messages.ts`. Les phases travaillent chacune dans leurs fichiers sans se marcher dessus. Un nouvel espace : créer `fr/<nom>.json` et `en/<nom>.json`, puis l'importer dans les deux catalogues de `messages.ts` (un test vérifie qu'aucun fichier n'est oublié).
- **Le français fait foi.** Sa forme type `t('…')` (`src/i18n/next-intl.d.ts`) : une clé inexistante est une erreur de typecheck. `src/i18n/messages.test.ts` vérifie que l'anglais a **exactement** les mêmes clés et les **mêmes arguments ICU** (noms, types `plural`/`select`, balises), que chaque message se parse, et qu'aucun n'utilise l'apostrophe droite `'` (en ICU elle échappe les accolades ; la typographie du produit est `’`).
- **Où ranger quoi :**

| Espace        | Contenu                                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| `common`      | actions génériques (`actions.retry`, `cancel`, `seeAll`, `join`…), repli des pseudos (`people`), `counts.*`      |
| `errors`      | `codes.<code>` (erreurs métier, cf. plus bas), `fallback.<clé>` par action, `generic`                            |
| `layout`      | en-tête, navigation, menu compte, pied de page, thème, langue, raccourcis, 404, erreurs                          |
| `metadata`    | slogan, descriptions, `titles.<page>` pour les `<title>`                                                         |
| `og`          | textes des images Open Graph, un sous-objet par image (`home`, puis `invite`, `list`, `results`)                 |
| `home`        | accueil et tableau de bord                                                                                       |
| `onboarding`  | pseudo, `/setup`                                                                                                 |
| `pwa`         | page hors ligne, puis bannière d'installation, notifications                                                     |
| `session`     | salle d'attente, vote (`vote.actions.<kind>` déjà posé : veto, no, yes, fav), résultats, duo, départage, règles… |
| `restaurants` | sélecteur, filtres, fiche, Google Places, amorçage                                                               |
| `lists`       | listes, partage, liste publique                                                                                  |
| `groups`      | groupes récurrents, invitations                                                                                  |
| `account`     | compte, statistiques, contraintes alimentaires, connexion, suppression                                           |
| `legal`       | confidentialité                                                                                                  |
| `changelog`   | chrome de `/nouveautes` (les notes de version elles-mêmes restent en français, cf. plus bas)                     |

### Conventions de clés

- `camelCase`, regroupées par écran puis par bloc : `home.hero.title`, `layout.accountMenu.confirmTitle`. Pas de clé qui recopie le texte français.
- Une clé par **sens**, pas par occurrence : « Réessayer » partout → `common.actions.retry`. Mais un même mot français qui se traduit différemment selon le contexte mérite deux clés.
- Les valeurs d'une énumération métier sont indexées par la valeur elle-même : `session.vote.actions.veto`, `layout.shortcuts.targets.newSession`. Côté code, la donnée porte l'identifiant (`id`, `kind`), jamais le libellé (voir `src/lib/shortcuts.ts`, `NAV_ITEMS`).
- Mise en forme dans le texte : balises ICU et `t.rich` (`"Où est-ce qu’on <brand>mange</brand> ?"`), jamais de concaténation de morceaux traduits séparément. Une phrase avec des valeurs est **un** message à arguments (`"{host} t’invite · {restaurants} · {participants}"`).
- Pluriels : toujours ICU, `{count, plural, one {# resto} other {# restos}}`. Le français met 0 au singulier, l'anglais au pluriel : ICU s'en charge, pas le code. Les compteurs réutilisables vont dans `common.counts`.
- Anglais naturel, pas mot à mot. Le ton est complice et sobre : « No more “whatever you want” », « Nah », « Works for me ». Guillemets anglais `“ ”`, apostrophe `’`.
- La marque (`onmangekoi`, le wordmark) ne se traduit pas.

## Dans les composants

| Où                                     | Traduire                                                                 | Langue / formatage                    |
| -------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------- |
| Server Component **synchrone**         | `const t = useTranslations('home')`                                      | `useLocale()`, `useFormatter()`       |
| Server Component **async**             | `const t = await getTranslations('home')` (dans le `Promise.all` du lot) | `await getLocale()`, `getFormatter()` |
| Client Component                       | `useTranslations` (le layout racine fournit `NextIntlClientProvider`)    | `useLocale()`                         |
| `generateMetadata`                     | `await getTranslations('metadata.titles')`                               | —                                     |
| Image Open Graph, manifest             | `getTranslations({ locale, namespace })` avec la langue de `params`      | la langue de `params`                 |
| Server Action, route handler           | `await getTranslations('…')` (langue de la requête)                      | `await getLocale()`                   |
| Hors React (domaine, `lib/`, use case) | **ne traduit pas** : renvoie un code, un identifiant ou des valeurs      | reçoit la `locale` en paramètre       |

- Les traducteurs s'appellent `t`, ou `t<Espace>` pour un second (`tCommon`) : la règle ESLint ne reconnaît que ces noms.
- `export const metadata = { title: '…' }` devient `export async function generateMetadata()`.
- Une donnée qui porte un libellé (tableau de constantes, `VOTE_ACTIONS`, `STEPS`) porte à la place une clé ou un identifiant ; le composant traduit.
- Le domaine qui fabrique des phrases renvoie une **description** (un `kind` + des valeurs) que le composant traduit. Ses tests vérifient la description, un test de composant vérifie le texte, en français **et** en anglais. Ce que la phase B a posé, à imiter :

  | Domaine                                | Renvoie                                                   | Traduit par                                              |
  | -------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------- |
  | `describeRules` (`session-rules.ts`)   | `RuleLine[]` : `{ kind: 'superlikes', count }`…           | `useRuleLineText()` (`components/session/rules-summary`) |
  | `jokerBadge`, `jokersSentence`         | `{ kind: 'remaining', count }`, `{ kind: 'both', … }`     | `session.vote.jokerBadge.*`, `session.deck.jokers.*`     |
  | `suggestionSummary` (`suggestions.ts`) | `{ recent, winners, days, fresh }`                        | un seul message ICU `plural` + `select`                  |
  | `blockedCount`, `ownConflict`          | un compte ; `{ kind: 'tag', tag }` / `budget` / `several` | `session.constraints.blocked`, `restaurants.notForMe.*`  |
  | `duoFinishedState` (`duo.ts`)          | `{ kind: 'partnerVoting', pseudo }`…                      | `session.finished.duo.*`                                 |
  | `mealAt` (`session-name.ts`)           | `'lunch'` / `'dinner'`                                    | `session.create.defaultName`, `session.duo.sessionName`  |
  | `VOTE_ACTIONS` (`vote.ts`)             | `kind` seulement                                          | `session.vote.actions/short/hints.<kind>`                |

- Une suite de libellés (« A, B et C », « budget, régime et adresse ») se joint avec `Intl.ListFormat` dans la langue courante (`joinNames(names, locale)`), jamais avec un « et » écrit en dur.
- Pseudos de repli : `usePeopleLabels()` (`src/i18n/use-people-labels.ts`) donne `{ guest, deletedParticipant }` pour `participantLabel`.
- **Image Open Graph avec des données** : un `alt` traduit passe par `generateImageMetadata`, ce qui fait de la route une route prérendue à la demande (`●`) — elle ne peut **plus lire de cookie** (500 « used IO that was not cached »). Les données viennent alors d'un client anonyme mis en cache (`'use cache'`), comme `getPublicResults` ou `getPublicSessionPreview` (`data-access/public-invitations.ts`) : c'est de toute façon ce que voit le robot d'aperçu, qui n'envoie aucun cookie. À retenir pour `l/[code]`.
- Tous les messages sont envoyés au client (`NextIntlClientProvider` sans filtre). Si le poids devient gênant, filtrer par espace de noms dans `src/app/[locale]/layout.tsx`.

## Formatage

`src/lib/format.ts` prend la langue en paramètre et formate dans le fuseau `Europe/Paris` (`TIME_ZONE`, `src/i18n/config.ts`) — sans fuseau fixe, le serveur (UTC) et le navigateur ne dateraient pas pareil.

- `relativeDate(iso, locale, now?)` — « il y a 5 minutes » / « 5 minutes ago », puis une date courte au-delà d'un mois.
- `percentLabel(ratio, locale)` — `42 %` / `42%`.
- `displayPseudo(pseudo, guestLabel)` et `participantLabel(profileId, pseudo, labels)` : passer `t('common.people.guest')` et `{ guest, deletedParticipant }` (`common.people`). Le français par défaut disparaîtra en phase C.
- `plural` et `countLabel` sont **dépréciés** (français seulement) : chaque appel devient un message ICU. Les supprimer quand le dernier appel a disparu (il n'en reste que dans `lists/`, `groups/`, `account/` et `l/[code]`).
- `distanceLabel(from, to, locale)` et `formatDistance(meters, locale)` (`lib/maps.ts`) — « 1,2 km » / « 1.2 km ».
- `formatDeadlineTime(closesAt, locale)` (`domain/session-deadline.ts`). `formatCountdown` reste neutre (`09:58`, `1 h 05`).
- Une date affichée dans un composant : `useFormatter().dateTime(date, { day: 'numeric', month: 'long' })` — fuseau du produit compris.
- Pour le reste (`Intl.NumberFormat('fr', …)` en dur), prendre la langue courante, ou `useFormatter()` / `getFormatter()` de next-intl.

## Erreurs

Le domaine ne connaît que des **codes**. Le texte vit dans `messages/<langue>/errors.json`.

- La base lève `raise exception 'omk:<code>'` ; l'application lève `new AppError('<code>', { valeurs })` (`src/domain/errors.ts`), au même format. Le code est typé (`ErrorCode`) : il doit exister dans `errors.codes` des messages.
- **Server Actions : la voie retenue est de renvoyer un message déjà traduit.** `return { error: await translateError(error, 'fallbackKey') }` (`src/i18n/server.ts`). Le contrat `{ error: string }` ne change pas : aucun composant n'a à connaître les codes. C'est la voie la moins invasive — les actions étaient déjà les seules à fabriquer le message.
- Côté client (réponse d'une route d'API, erreur réseau) : `const describe = useErrorMessage()` (`src/i18n/use-error-message.ts`).
- Refus décidé par l'action elle-même (pas de pseudo, identifiant illisible) : `return { ok: false, error: await errorMessage('not_authenticated') }` (`src/i18n/server.ts`) — le même texte que si la base l'avait levé. Les replis « Formulaire invalide », « Session invalide », « Requête invalide »… sont des codes (`invalid_form`, `invalid_session`, `invalid_request`).
- Validation Zod : **chaque** message de schéma s'écrit `omkMessage('<code>')`, et l'action le traduit avec `translateIssue(issue, await errorMessage('<repli>'))`. C'est fait pour `schemas/session.ts`, `vote.ts`, `restaurant.ts` et `place.ts` ; pour les autres : ajouter un code dans `errors.codes`, remplacer le texte par `omkMessage('…')`, passer l'action à `translateIssue`. Un code ne porte pas de valeurs : une borne (« 100 caractères ») s'écrit en clair dans le message.
- Un nouveau code : `fr/errors.json` **et** `en/errors.json`, sous `codes`. `src/i18n/errors.test.ts` vérifie que chaque code se traduit dans chaque langue.

## Tester

- **Composants** : `renderWithIntl(ui, { locale })` (`src/test/render.tsx`) au lieu de `render` — le vrai `NextIntlClientProvider`, les vrais messages, en français par défaut. Les tests existants cherchent des textes français : ils restent tels quels. Ajouter un cas `locale: 'en'` quand le composant a une logique propre à la langue (pluriels, dates, raccourcis).
- **Messages** : `bun run test src/i18n` (parité des clés et des arguments, parse ICU, apostrophes).
- **E2E** : Playwright tourne en `fr-FR` ; `e2e/i18n.spec.ts` part d'un navigateur `en-US` (langue détectée, sélecteur, cookie, 404, et depuis la phase B la création d'une session jusqu'à la salle d'attente). La phase C fera tourner les parcours dans les deux langues — par exemple un second projet Playwright en `en-US`, avec des sélecteurs par rôle et des textes lus dans `messages/`.
- **Build** : `bun run build` doit lister chaque page deux fois (`/fr/…`, `/en/…`) en `◐` (Partial Prerender). Une page qui passe en `ƒ` a lu la requête hors d'un `<Suspense>`.
- À la main : `curl -H 'Accept-Language: en' localhost:3000/` ou le sélecteur du pied de page.

## ESLint

`i18next/no-literal-string` (`eslint.config.mjs`) interdit le texte en dur dans le JSX (texte et attributs `aria-label`, `title`, `placeholder`, `alt`…). Elle ne vise que les dossiers déjà extraits (`I18N_EXTRACTED`), en `warn` — bloquant quand même, `bun run lint` tournant avec `--max-warnings 0`. Chaque phase ajoute ses dossiers à la liste ; la phase C la remplace par `src/**/*.tsx` et la passe en `error`.

La règle ignore les attributs techniques (`className`, `href`, `loading`, `sizes`, `value`, `*Name`, `data-*`, `on*`, `context`…) et les appels `t…()` et `captureEvent()`. En mode `jsx-only`, elle ne voit pas le texte hors JSX : les `metadata`, les `title:` de `generateMetadata`, les messages de Server Actions et les phrases du domaine se relisent à la main (un `grep` sur les accents et « ’ » suffit à les trouver).

## Reste à extraire

Après la phase B, il reste en français, par dossier :

**Pages** (`src/app/[locale]/(app)/`) : `account`, `groups`, `l/[code]` (et son image Open Graph : `alt` par `generateImageMetadata`, données par un client anonyme en cache — voir plus haut), `legal/privacy`, `lists`, `lists/new`, `lists/[code]`, `nouveautes` — `metadata`/`generateMetadata` compris.

**Composants** (`src/components/`) : `lists/`, `groups/` (dont `save-group-form`, rendu sur le classement), `account/` (sauf les régimes de `food-constraints-form`, déjà lus dans `restaurants.tags`), `changelog/`, `analytics/` (bannière de consentement, préférence), `pwa/` (sauf `retry-button`), `og/` (textes passés en props, déjà traduisibles), `ui/` (libellés d'accessibilité : `copy-button`, `two-step-button`, `spinner`, `dialog`, `avatar`, `progress`… — ils apparaissent donc encore en français sur les écrans de session, par exemple « Copié » après une copie de lien).

**Hors composants** :

- `src/actions/` : `lists.ts`, `groups.ts` (dont `inviteGroupToSessionAction`, appelé depuis la salle d'attente), `account.ts`, `auth.ts` (`humanizeAuthError`), `profile.ts`, `food-constraints.ts` — replis de validation, « Tu dois d’abord choisir un pseudo. », messages de succès. Passer à `errorMessage(code)` et `translateIssue`.
- `src/domain/schemas/` : `list.ts`, `group.ts`, `profile.ts`, `auth.ts`, `food-constraints.ts`, `push.ts` (messages Zod).
- `src/domain/push.ts` (titres et corps des notifications) et `src/lib/pwa/service-worker.ts` (`lang: 'fr'`). Les notifications partent du serveur vers des abonnés dont on ignore la langue : il faudra la retenir à l'abonnement (colonne `locale` dans `push_subscriptions`, lue par `api/push/dispatch`), puis traduire avec `getTranslations({ locale })`.
- `src/lib/format.ts` : `plural`, `countLabel`, et les replis français de `displayPseudo` / `participantLabel` (`FRENCH_PEOPLE_LABELS`, `DELETED_PARTICIPANT`) — à supprimer quand `lists/`, `groups/` et `account/` seront extraits.
- `src/components/changelog/release-note-card.tsx` (`dateFormatter`). Le contenu des notes de version (`src/content/changelog/entries.ts`) et le flux RSS restent en français : c'est du contenu éditorial, rédigé après chaque release.
- `src/data-access/places.ts` : `languageCode: 'fr'` des appels Google (noms et adresses renvoyés en français) — à décider : suivre la langue de la requête, ou garder le français pour un catalogue partagé.
- Noms de session proposés (« Déj du mardi », « À deux · déj du mardi ») : ils sont écrits dans la langue de qui crée la session et **stockés** tels quels ; les autres participants les voient dans cette langue. C'est voulu (c'est un nom, pas une interface), mais à garder en tête.
- E-mails d'authentification : ceux de Supabase Auth, configurés hors du dépôt — hors du périmètre de l'app.
